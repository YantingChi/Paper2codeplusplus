# ------------------------------------------------------------------------------
# Logic Analysis for config.py
#
# This configuration file consolidates all hyperparameter settings and 
# experiment configurations to ensure consistency across modules.
#
# The settings below derive directly from both the BE‑CBO paper and the 
# comprehensive roadmap outlined in the plan and design documentation. 
#
# Key Sections:
#
# 1. Training Parameters:
#    - optimizer: "Adam" 
#         → Used for both training the deep ensemble classifier and for the 
#           pre-optimization step in the acquisition optimizer.
#    - learning_rate: 3e-4
#         → This learning rate (as recommended in the paper and config.yaml)
#           will be used with the Adam optimizer for the 1,000 iterations of 
#           training (via variational inference using the evidence lower bound, ELBO).
#    - iterations: 1000
#         → Sets the number of gradient descent updates per training cycle of 
#           the deep ensemble. Using ELBO instead of MLE is crucial for well‐calibrated 
#           uncertainty estimates, directly impacting the dynamic bound computation.
#
# 2. Ensemble Configuration (Deep Ensemble Classifier Parameters):
#    - size: 5
#         → Defines the number of MLP members in the ensemble. The paper 
#           shows that performance is relatively insensitive between 3 to 8 members.
#    - layers: 4
#         → Each MLP will have four fully-connected layers with ReLU activation. 
#           This depth supports learning complex constraint boundaries.
#    - neurons_formula: "64 * floor(log2(d))"
#         → Specifies the number of neurons per hidden layer. The formula scales 
#           the network capacity with the problem dimension (d), as recommended 
#           to handle higher-dimensional design spaces.
#    - activation: "ReLU"
#         → We use ReLU activations between layers as a standard choice.
#    - loss: "Variational Inference (ELBO)"
#         → Training uses the variational inference approach (ELBO loss) instead 
#           of standard binary cross-entropy to yield more calibrated uncertainties.
#    - use_dropout: false
#         → As per paper recommendations, dropout is not applied.
#
# 3. GP Surrogate Settings:
#    - kernel: "Matern5/2"
#         → This kernel (with BoTorch default hyperparameters) is used to model 
#           the objective function (f(x)). Its default parameters are assumed to 
#           be sufficient per the paper’s experiments.
#
# 4. Bayesian Optimization (BO) Settings:
#    - initial_samples: 10
#         → Number of design points to generate initially (using a Sobol sequence), 
#           seeding the BO loop.
#    - total_evaluations: 200
#         → Total evaluation budget per run, ensuring consistency with the 
#           experimental protocol described in the paper.
#    - random_seeds: 10
#         → Number of independent runs (random seeds) for statistical robustness.
#    - acquisition_function: "Expected Improvement (EI)"
#         → EI is chosen as the acquisition function, though the method is generic 
#           for alternatives (e.g., UCB) if desired.
#    - dynamic_bound: "l(x) = 0.5 - sigma_E(x)"
#         → Defines the lower bound on the classifier prediction. sigma_E(x) is 
#           the uncertainty (standard deviation) estimated from the deep ensemble. 
#           This dynamic setting encourages sampling near the boundary between feasible 
#           and infeasible regions, as the paper emphasizes.
#    - optimizer: "SLSQP (with pre-optimization using Adam)"
#         → The candidate solution from the constrained acquisition optimization 
#           is obtained via a two-step process: first nudging with Adam (to satisfy 
#           the dynamic constraint) and subsequently refining via SLSQP.
#
# 5. Benchmark Settings:
#    - problems: [ "Townsend", "Simionescu", "LSQ", "Three-bar Truss", "Tension-Compression String", 
#                  "Welded Beam", "Gas Transmission Compressor", "Pressure Vessel", 
#                  "Speed Reducer", "Planetary Gear Train", "Rolling Element Bearing", "Cantilever Beam" ]
#         → A list of all benchmark problems to be used in experiments. Each problem’s 
#           objective function and unknown binary constraint are defined in benchmark.py.
#
# 6. Logging Configuration:
#    - verbosity: "INFO"
#         → Sets the level of logging output for experiment traceability.
#    - save_results: true
#         → Indicates whether experiment results should be saved for further analysis.
#
# 7. General Settings:
#    - device: "cpu"
#         → Defines the computation device. This setting ensures all modules operate 
#           consistently, and can be switched to "cuda" if GPU acceleration is available.
#    - seed: 42
#         → Global seed value to guarantee reproducibility across all modules and random 
#           number generations (e.g., initial sample selection, model initialization, etc).
#
# Usage in the System:
# - Modules such as gp_surrogate.py, deep_ensemble.py, and acquisition.py import this file 
#   to set their hyperparameters. For instance, the DeepEnsembleClassifier will parse the 
#   'ensemble' section for network architecture parameters.
# - The BOTrainer (botrainer.py) will reference BO settings (initial_samples, total_evaluations, 
#   random_seeds) to orchestrate the main loop.
# - The Benchmark module (benchmark.py) will use the list of problems to instantiate various 
#   benchmark functions.
#
# Clarifications & Open Points:
# - The specific numerical values for the pre-optimization (Adam) and SLSQP tolerances are not 
#   defined here; these may be added in future updates if experimental tuning reveals a need.
# - The 'neurons_formula' string will be interpreted by the deep ensemble module when the problem 
#   dimension (d) is known, ensuring the correct network capacity.
# - Any further experimental details (e.g., additional loss hyperparameters for ELBO) should 
#   be appended as needed.
#
# This configuration file is the central hub for all experimental settings and should be 
# imported by every module to ensure that the experimental reproduction adheres rigorously 
# to the BE‑CBO methodology described in the paper.
